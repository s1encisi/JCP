# 系统架构与实现边界

## 两种运行环境

公开演示由 `run_demo.py` 启动，设置 `JCP_DEMO=1`，使用确定性的合成公式提供预测。它不读取工业数据，也不加载 joblib 或 PyTorch 权重。演示中的 NSGA-II 是实际调用 pymoo 完成的优化计算。

研究模式由 `interface/app_v2.py` 启动，读取本地可信资产。三个工况各使用电压、Cu 和 As 模型；保存的 PPO 策略提供偏好条件化增量动作。缺少模型、特征不匹配或推理失败会返回明确错误，不降级为随机预测。

## 数据和计算约定

`process_contract.py` 集中定义：

- 三种工况的输入字段、单位、取值范围和别名映射。
- Cu_out ≤ 8.0 g/L、As_out ≥ 4.0 g/L、J ≤ 340 A/m²、V_cell ≤ 2.5 V、Cu_out/As_out ≤ 0.8。
- 电流密度按 `I / (35 × 1.100 × 1.029 × 2)` 计算。
- 串联工况检查两个单元中较大的电流密度。研究电压模型提供平均单元电压，电压判定与该预测口径一致，不将它解释为独立测得的各单元电压。
- PPO 输出按 `[ΔCu_in, ΔT, ΔI, ΔQ, ...]` 及训练时缩放量解码。界面推理固定进液浓度和批次时长，只更新可调整变量。

这些阈值是现有研究实现的配置，不是适用于所有工厂的通用安全标准。约束满足表示模型与当前配置下的检查结果，最终操作建议需要人工审阅。

## 代理模型调用

`model_runtime.py` 按工况构造特征。先预测电压，再将预测电压及功率特征用于浓度模型；有 `feature_names_in_` 时按模型记录的顺序生成 DataFrame，并拒绝不匹配的特征集合。

研究模式使用请求中提供的时间戳，未提供时使用当前时间。模型的未来时段泛化能力需要通过时间留出与后续数据单独评估；改变时间输入不构成在线学习。

串联经济计算采用两单元平均流量，避免界面与统一比较口径混用。合成演示使用单独标注的经济系数，不把其数值当作企业财务数据或收益预测。

## 优化和交互

`demo_optimization.py` 定义四目标、五约束的 ElementwiseProblem，运行真实 NSGA-II。输入中的 Cu_in 和时长固定；温度、电流、流量在各工况范围内搜索。默认种群64、30代、种子42，配置和实际评价次数随结果保存。

从可行非支配解中选择质量、节能、经济与均衡方案。保存上限使用保留代表点的确定性最大最小距离选点；界面应用方案使用未舍入的结果，显示时才格式化数字。

浏览器采用同源 HTTP 请求和任务轮询，不依赖外部 JavaScript CDN。一个进程同时允许一个优化任务；重复提交返回409。完成、失败、找不到任务分别处理，失败不会触发成功提示或替代结果。

## 本地持久化与文件边界

SQLite 保存经过验证的输入、实际实验结果和反馈。连接通过统一上下文管理器提交、回滚并关闭，兼容 Windows 文件锁行为。CSV 导出从实验记录读取本次计算的候选行。

文件导入限制为 CSV/XLSX，最大4 MiB、2,000行。整批数据验证通过后才写库，临时上传使用随机文件名并在处理后删除。公开接口禁止任意数据库连接和自定义 SQL。

服务器默认绑定回环地址、关闭 debug，限制 Host，并拒绝跨源写请求。仅返回明确允许的页面、工作流脚本及生成的 CSV 导出；源码、数据库、上传文件和模型文件不作为静态资源提供。

这是本地工具的运行边界，不等同于具备登录、权限隔离和高可用能力的生产 Web 服务。

## 研究模块的角色

原有 ExtraTrees、SHAP/PDP、NSGA-II、PPO-Lagrangian 和补充实验代码保留在研究目录。正式训练使用本地 CLI，避免一个网页点击意外启动长时间、多进程实验。

公开演示验证的是软件数据流和优化调用的完整性。研究算法的预测精度、跨时段泛化、鲁棒性和经济优势应以相应数据、拆分和实验输出为依据，不能由演示页面或软件测试通过来替代。
